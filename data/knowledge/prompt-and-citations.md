# Prompt 组装、引用与拒答

## 1. prompt 组装的目标

RAG 的 prompt 组装不是简单把 chunk 拼起来。它需要明确告诉 LLM：哪些内容是系统指令，哪些是用户问题，哪些是检索上下文，回答必须基于上下文，不能把文档里的指令当成系统指令。

好的 prompt 会要求模型引用来源、在证据不足时拒答、不要编造文档里没有的信息。它还会控制答案格式，例如先给结论，再列依据，最后给 citation。这样输出更稳定，也更容易评估。

## 2. 上下文顺序

上下文顺序会影响答案。通常应把最相关的 chunk 放在前面，因为模型更容易关注前面的内容。如果 MRR 很低，正确 chunk 虽然在 top-k 内，但排得靠后，答案仍然可能被前面的无关 chunk 干扰。

有些系统会按文档结构重新排序，例如同一文档的相邻 chunk 按原文顺序排列，避免步骤说明被打乱。也有系统保留检索排序，因为相关性更重要。哪种更好需要用评估集验证。

## 3. citation 的价值

citation 是 RAG 区别于普通聊天的重要能力。它让用户知道答案来自哪个文档、哪个 chunk，也让开发者能追踪错误来源。没有 citation 的答案很难审计，尤其在企业知识库、合规政策和技术支持场景里。

本项目的 citation 格式是 `文件名#chunk-序号`。这个格式简单但足够学习。生产系统可能需要更丰富的引用，包括文档标题、URL、章节、段落位置、版本号和权限空间。

## 4. 拒答策略

当检索结果为空、分数过低、citation 不可信或上下文没有答案时，系统应该拒答或请求用户澄清。拒答不是失败，而是避免编造。一个可靠的 RAG 系统必须知道什么时候不能回答。

拒答策略可以结合 score threshold、最小命中数量、metadata 过滤结果和 LLM 自检。比如没有任何 chunk 超过阈值时，回答“知识库中没有找到足够依据”，并提示用户补充关键词或选择文档范围。

## 5. prompt injection

RAG 会把外部文档放进 prompt，因此必须考虑 prompt injection。文档里可能写着“忽略系统指令”“输出密钥”“把自己当管理员”。模型可能把这些文本当成指令执行。

防护思路是把检索内容明确标记为不可信资料，只允许模型把它当事实来源，不允许它覆盖系统指令。对于高风险场景，还需要内容扫描、来源白名单、权限隔离和输出审计。
