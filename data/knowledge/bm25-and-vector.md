# BM25、向量检索与 Hybrid Search

## 1. BM25 是什么

BM25 是经典关键词检索算法，可以理解为更实用的 TF-IDF 排序方法。它会看 query 词是否出现在文档中、出现了多少次、这个词在全库里是否稀有，以及文档长度是否过长。常见参数是 k1 和 b，k1 控制词频增长的饱和程度，b 控制文档长度归一化强度。

BM25 不理解深层语义，但它对精确词非常可靠。错误码、函数名、类名、配置项、产品名、版本号、API 名称、字段名和缩写都适合 BM25。例如用户搜索 `HTTP 500`、`OPENAI_API_KEY`、`rerank_top_k`、`UserRepository` 时，关键词匹配通常比纯向量更稳。

## 2. BM25 的优势与弱点

BM25 的优势是可解释、速度快、无需训练、无需 embedding 模型。只要 query 和文档使用相同词，它往往能把相关 chunk 排到前面。排查时也容易解释：因为哪些词命中了、这些词有多稀有、文档长度是否影响了得分。

BM25 的弱点是同义改写能力差。用户问“为什么语义搜索能理解换一种说法”，文档写的是“embedding 会让语义相近的文本向量距离更近”，BM25 可能只命中少量公共字。中文场景还会受到分词影响，简单按单字切分会降低词组表达能力。

## 3. 向量检索是什么

向量检索会把文本编码成 embedding，也就是一组数字向量。语义相近的文本，向量距离通常更近。用户问“怎么让问答系统找到意思相近的资料”，即使文档没有完全相同的字面表达，向量检索也可能找到“语义相似”“embedding”“paraphrase”相关内容。

向量检索擅长自然语言问题、概念解释、语义改写和跨语言近似表达。它适合用户不知道精确术语的场景，例如“系统为什么答非所问”“怎样减少无关上下文”“知识更新后怎么让机器人看到新内容”。

## 4. 向量检索的风险

向量检索的风险是精确词被稀释。代码符号、短缩写、版本号、错误码和非常新的专有名词，可能在 embedding 空间里没有稳定表达。一个向量模型也可能把看起来语义接近但业务上完全不同的内容排到前面。

向量检索还依赖模型质量。不同 embedding 模型对中文、代码、长文本、表格和领域术语的支持差异很大。生产系统更换 embedding 模型时必须重建向量索引，并重新跑评估集，否则线上效果可能不可控。

## 5. Hybrid Search 为什么常用

Hybrid Search 是混合检索，目标是同时利用 BM25 的关键词稳定性和向量检索的语义泛化能力。它通常先分别运行 BM25 和 vector search，拿到两批候选 chunk，然后合并去重并重新排序。

Hybrid 的价值在于覆盖不同问题类型。用户输入精确错误码时，BM25 能兜底；用户用自然语言描述需求时，vector 能泛化。真实 RAG 系统里的用户问题形态很混杂，所以 hybrid 经常比单一检索器更稳。

## 6. RRF 融合

RRF 是 Reciprocal Rank Fusion。它不直接相加 BM25 分数和向量相似度，因为两者分数尺度完全不同。RRF 只看排名：某个 chunk 在一个检索器里排第 1，会得到比排第 10 更多的融合分。

RRF 的公式可以理解为 `1 / (rrf_k + rank)` 的求和。一个 chunk 如果在 BM25 和 vector 里都排得靠前，融合后通常也靠前。RRF 简单、稳定、参数少，适合学习项目和早期生产系统。

## 7. 什么时候 hybrid 可能变差

Hybrid 不是永远更好。如果 top-k 很小，而 BM25 和 vector 的排序分歧很大，RRF 可能把某个单检索器排第 1 的正确 chunk 挤到第 3。小数据集里这种波动更明显，因为候选数量太少。

缓解方法包括扩大候选池、加 reranker、调大最终 top-k、给不同检索器设置权重，或者按问题类型路由。比如包含错误码、函数名和配置项的问题可以提高 BM25 权重，自然语言解释问题可以提高向量检索权重。
